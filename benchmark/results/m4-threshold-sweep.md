## Chosen operating point

**threshold = 0.85**, measured hit rate 73.7% and false-hit rate 0.0%, both with the entity guard active.

Justification: among the candidate thresholds that keep the cache meaningfully useful (guarded hit rate >= 10%, a floor only to exclude degenerate near-zero-hit-rate points), this is the one that minimises the guarded false-hit rate - the Pareto-best point actually measured, not a guess. It clears AC3 (hit rate >= 35%) on this corpus. This is the sweep's in-sample optimum, not the product default (`aether.cache.default-threshold`): the guard's heuristics were written against these adversarial pairs, so a low guarded false-hit rate here does not show it generalises. docs/design/cache-correctness.md explains why the default stays where it is.

**Residual false hits at the chosen threshold** (adversarial pairs the guard still allows):

None on this corpus. The corpus's adversarial pairs informed the guard's heuristics, so this is an in-sample result; see docs/design/cache-correctness.md for the guard's known blind spots.
